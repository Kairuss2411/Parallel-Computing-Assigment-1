Repository review (based on uploaded branch ZIP)

Build repair:
- include/common.h in the uploaded ZIP was missing shared helpers used by lock code:
  hw_threads(), now_ms(), pin_thread(), cpu_relax(), do_not_optimize(),
  is_prime(), CACHELINE, and g_max_delay.
- Added these helpers to include/common.h.
- Avoided duplicate cpu_relax() definition between common.h and barrier.h.

Validation performed in a Linux environment:
- `make -j2` builds all four current executables after the fix.
- `./build/test_barrier` passes for srb, srb_backoff, std_barrier, and
  pthread_barrier at thread counts 1, 2, 4, and 8 in the included test.
- `./build/test_lock 10 1` passes all included lock tests and detects the
  intentionally broken lock.
- Small runs of all three barrier benchmark algorithms and a lock benchmark
  completed successfully.
- The default `make test` run was not confirmed to finish within the available
  execution window; use the shorter lock test command first, then run the full
  default test on your machine with enough time.

Important gaps:
- The project is currently POSIX/Linux-oriented, not native MSVC Windows:
  include/lock_baseline.h includes pthread.h and omp.h, and Makefile uses g++,
  -pthread, -fopenmp and Unix shell commands. Recommended Windows route: WSL2
  with Ubuntu, g++, make, and OpenMP support.
- Task 3 (Concurrent Counters) is not present in the uploaded source tree:
  there are no counter implementation, counter test, or counter benchmark files.
- README.md has stale barrier instructions: it mentions `--mode=all`,
  `omp_barrier`, `barrier_sense.h`, and positional test arguments that do not
  match the actual source files. Actual barrier algorithms in bench_barrier.cpp
  are srb, srb_backoff, std_barrier, and pthread_barrier only on supported POSIX.
- The sense barrier test is a useful basic check but is not a complete formal
  proof of correctness; stress-test and review it before reporting results.
